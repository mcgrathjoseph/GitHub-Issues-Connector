Full Response:
Short answer: the screenshots are most likely showing the Microsoft 365 Agents Toolkit in VS Code, plus MCP tooling. 
They are related to the Microsoft 365 Agents ecosystem, but they are not automatically the same thing as “an Agents SDK project”.

What the screenshots suggest:
1) The file m365agents.local.yml strongly indicates a Microsoft 365 Agents Toolkit project. 
Microsoft documents m365agents.yml as the main Agents Toolkit project file and m365agents.local.yml as the local override used for local execution/debugging.
2) The mcp.json file indicates Model Context Protocol server configuration in VS Code / GitHub Copilot Agent mode. 
Microsoft also documents using .vscode/mcp.json together with the Microsoft 365 Agents Toolkit MCP Server and MCP-based Copilot extensibility workflows.
3) Therefore, your VS Code setup fits on the “developer/pro-code side” of the picture, not the Copilot Studio web UI side.

Important nuance:
- Agents Toolkit is a developer toolchain / extension / deployment helper.
- Agents SDK is the runtime/framework you code against when building custom engine agents.
- An Agents Toolkit project can scaffold or manage several things: Teams apps, declarative agents, plugins, connectors, and also some Agents SDK-based projects.

So are your screenshots “MS Agents SDK”?
- Maybe partly, but not necessarily.
- They are definitely in the Microsoft 365 Agents Toolkit world.
- They are only an Agents SDK project if the sample/template itself is built on the Microsoft 365 Agents SDK runtime.

For your specific GitHub Issues Connector example:
Microsoft’s sample describes a broader solution that combines a Graph connector, webhook/Azure Function, declarative agent, and API plugin. 
That kind of project can be created and managed through toolkit files like m365agents.local.yml without being a pure custom-engine Agents SDK bot.

Best mental model:
- Copilot Studio = browser UI builder/orchestrator
- Agents Toolkit in VS Code = developer scaffolding/provisioning/debugging/deployment layer
- Agents SDK = code framework/runtime for custom agents
- MCP = a protocol/tooling bridge that VS Code/GitHub Copilot can use to work with agent/dev tools and MCP-exposed services

Bottom line:
Your screenshots are best described as:
“Microsoft 365 Agents Toolkit + MCP tooling in VS Code”.
That sits beside Copilot Studio, and can support Agents SDK projects, but is not identical to Copilot Studio and not automatically identical to the Agents SDK itself.
